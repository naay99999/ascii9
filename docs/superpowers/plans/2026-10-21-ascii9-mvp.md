# ASCII9 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-screen static web app that converts an image to ASCII art in the browser and downloads it as PNG, JPG or TXT at exact social and wallpaper sizes.

**Architecture:**
- The conversion engine is a set of pure TypeScript modules under `src/engine/`. It runs inside a Web Worker that downsamples with `OffscreenCanvas`, and returns a typed-array cell grid.
- One canvas renderer (`src/render/`) draws that grid both for the on-screen preview and for exports, so the preview always matches the download.
- A thin Svelte 5 UI holds the settings in a single rune store, which persists to `localStorage`.

**Tech Stack:** Svelte 5, Vite, TypeScript, Vitest, `@fontsource/inter` and `@fontsource/jetbrains-mono` (self-hosted fonts), and plain CSS with custom properties.

**Spec:** `docs/superpowers/specs/2026-10-21-ascii9-mvp-design.md`. The conversion maths it cites is in `prd.md` §4.3–4.4.

## Global Constraints

- **Hosting:** static only (Vercel). No server code.
- **Privacy:** no network request carries image data. Fonts are self-hosted, so the page makes no Google Fonts calls.
- **Runtime dependencies:** `svelte`, `@fontsource/inter` and `@fontsource/jetbrains-mono` only. There is no router, animation library, toast library, UI kit or Tailwind.
- **Browsers:** latest two versions of Chrome, Safari, Firefox and Edge, including iOS Safari and Android Chrome.
- **Look:**
  - Colours: ground `#000`, panel `#111`, controls `#2a2a2a`; text `#fff`, `#b4b4b4`, `#949494`.
  - There is no accent hue in the UI.
  - No borders or shadows on resting surfaces. No gradients, glows, scanlines, terminal frames or emoji.
  - The primary button is a white pill with black text. Selected chips and segments are inverted.
  - UI font is Inter (400/500/600). Art font is JetBrains Mono 400.
- **UI copy:** English, sentence case.
- **Accessibility:** every control is reachable by keyboard and labelled, with a visible focus ring. Text contrast is at least 4.5:1. Touch targets are at least 44 px on mobile.
- **Input limits:** MIME type `image/*` and size ≤ 10 MB (10 × 1024 × 1024 bytes).
- **Export sizes:**
  - 1:1 → 1080×1080
  - 4:5 → 1080×1350
  - 9:16 → 1080×1920
  - 16:9 → 2560×1440
  - Original → long edge 2048
- **File names:** `ascii9-YYYY-MM-DD.<ext>`, using the local date.
- **Performance:** a preview update within about 150 ms at 120 columns. The UI stays responsive at 200.
- **Storage:** the `localStorage` key is `ascii9:settings:v1`. Every access is wrapped in try/catch. The image itself is never stored.

## Review Focus

1. **Undecodable "images"** (HEIC on desktop Chrome, a corrupt PNG, a `.svg` with no size). The user should see "Couldn't read that image." and the current image should stay. *Pinned by: Task 7, `loadBitmap rejects…`.*
2. **Extreme sizes and shapes** (a 1×1 PNG, a 12000×800 panorama, a 9000×9000 photo). There should be no crash, and the grid should have at least 1 row and 1 column. Big images are downscaled before they reach the worker. *Pinned by: Task 3, `gridSize never returns zero`, and Task 7, `loadBitmap caps long edge`.*
3. **Odd custom charsets.** An empty string falls back to Classic. A single glyph fills every cell. `<&">` and multi-codepoint emoji render as single cells. *Pinned by: Task 2, ramp tests.*
4. **Paste where it doesn't belong.** Pasting text into the hex field, or pasting non-image clipboard data, must not be hijacked or raise an error. *Pinned by: Task 7, `imageFromClipboard` tests, and Task 8, the paste guard.*
5. **Transparent PNGs and stale storage.** Transparent pixels composite over black and become spaces. Corrupt or old stored settings merge over the defaults. *Pinned by: Task 4, `transparent pixels become spaces`, and Task 7, `loadSettings` tests.*

  ```ts
  // writes adjusted r,g,b into out[0..2]; values 0–255 integers
  function adjustRGB(r: number, g: number, b: number, look: LookSettings, out: Uint8Array): void
  function luminance(r: number, g: number, b: number): number      // 0.299R+0.587G+0.114B

  function cellColor(look: LookSettings, rgb: [number,number,number], L: number, out: Uint8Array): void
  ```

- [ ] **Step 1: Write the failing tests:**
  - **tone:**
    - With the default look but contrast 0 and gamma 1, `adjustRGB(100,150,200)` returns `[100,150,200]`.
    - Brightness 100 makes `(0,0,0)` → `[255,255,255]`.
    - Contrast 100 makes 192 → 255 and 63 → 0.
    - Gamma 2 makes 128 → 64 (±1).
    - With `colorMode:'image'`, saturation 0 makes `(255,0,0)` → `[76,76,76]` (±1).
    - With `colorMode:'mono'`, saturation 0 leaves `(255,0,0)` unchanged.
    - The order follows PRD §4.3 steps 4–5.
  - **edges:**
    - A uniform 5×5 image gives all zeros, including the border pixels. There is no black frame.
    - A vertical step edge gives non-zero values in the columns next to the step.
    - `blendEdges` with k=0 leaves its input unchanged. With k=1 it replaces RGB with the edge value and leaves alpha alone.
  - **ramp:**
    - `splitGlyphs('a❤️b☘️')` returns `['a','❤️','b','☘️']`.
    - `splitGlyphs(' <&">')` has length 5.
    - With `charset:''`, `rampFor` returns the Classic ramp.
    - For `style:'blocks'`, `rampFor` returns `[' ','░','▒','▓','█']` whatever the charset.
    - A charset without a leading space gets `' '` prepended.
    - `glyphIndex(255,10,false)` is 9, `glyphIndex(0,10,false)` is 0, and `glyphIndex(255,10,true)` is 0.
    - `glyphIndex(x,1,false)` is 0.
  - **colour:**
    - `parseHex('#00FF9f')` returns `[0,255,159]`.
    - Mono writes `monoColor` whatever the input.
    - Image writes the given rgb.
    - Duotone with `#000000`→`#ffffff` gives `[128,128,128]` (±1) at L=128.
    - Duotone with invert at L=255 gives `duo1`.
- [ ] **Step 2:** Run `npx vitest run tests/engine`. Expected: the new tests FAIL.
- [ ] **Step 3:** Implement the four modules.
  - `adjustRGB` applies, in order: gamma, brightness, contrast, clamp, then saturation (only when `colorMode==='image'`).
  - `glyphIndex` is `Math.round((invert ? 255-L : L) / 255 * (n-1))`, clamped to `[0, n-1]`.
  - In `cellColor`, duotone uses `t = (invert ? 255-L : L)/255`.
  - In `sobel`, out-of-range neighbours read the nearest edge pixel.
  - `splitGlyphs` falls back to `Array.from` when `Intl.Segmenter` is missing.

### Task 3: Grid and export sizing

**Files:**
- Create: `src/engine/layout.ts`
- Test: `tests/engine/layout.test.ts`

**Interfaces:**
- Consumes: `LayoutSettings`, `Frame` (Task 1).
- Produces:
  ```ts
  const FRAME_SIZES: Record<Exclude<Frame,'original'>, [number, number]>
  interface GridPlan { cols: number; rows: number; crop: { sx: number; sy: number; sw: number; sh: number } }
  // cellAspect = cell width / cell height (≈0.6)
  function gridSize(imgW: number, imgH: number, layout: LayoutSettings, cellAspect: number): GridPlan
  function exportSize(layout: LayoutSettings, plan: GridPlan, cellAspect: number): [number, number]
  ```

### Task 6: Worker and converter client

**Files:**
- Create: `src/worker/convert.worker.ts`, `src/lib/converter.ts`
- Test: `tests/lib/converter.test.ts`

**Interfaces:**
- Consumes: `convert`, `autoAdjust` (Task 4); `gridSize` (Task 3); `Settings`, `Grid` (Task 1).
- Produces:
  ```ts
  // worker messages
  type ToWorker = { type: 'image'; bitmap: ImageBitmap }
               | { type: 'convert'; id: number; settings: Settings; cellAspect: number }
               | { type: 'auto'; id: number }
  type FromWorker = { type: 'grid'; id: number; grid: Grid; plan: GridPlan }
                 | { type: 'auto'; id: number; result: { brightness: number; contrast: number; gamma: number } }
                 | { type: 'error'; id: number; message: string }
  interface WorkerLike { postMessage(m: ToWorker, transfer?: Transferable[]): void; onmessage: ((e: { data: FromWorker }) => void) | null }
  function createConverter(worker: WorkerLike, onGrid: (g: Grid, plan: GridPlan) => void, delayMs?: number /* 60 */): {
    setImage(bitmap: ImageBitmap): void       // posts immediately, then schedules convert
    request(settings: Settings, cellAspect: number): void   // debounced
    autoAdjust(): Promise<{ brightness: number; contrast: number; gamma: number }>
    dispose(): void
  }
  ```
  - The worker keeps the last bitmap.
  - On `convert` it calls `gridSize`, draws the crop onto an `OffscreenCanvas(cols, rows)` with `imageSmoothingQuality = 'high'`, applying `scale(-1,1)` when `flipH` is set. It then reads `getImageData` and calls `convert`.
  - It posts the grid back with `index.buffer` and `rgb.buffer` transferred.
  - `auto` draws at a width of 200 and calls `autoAdjust`.

- [ ] **Step 1: Write the failing tests** with a fake `WorkerLike` and Vitest fake timers:
  - Three `request` calls within 60 ms post one `convert` message, carrying the last settings.
